# dsh-locale-ru

Russian language pack for the [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) web GUI.

[Русская версия](README.ru.md) · [Правила перевода](TRANSLATION.md)

DeepSeek Harness ships its interface in English and Simplified Chinese. This plugin adds Russian as a third selectable language and covers the whole client surface: **2,444 strings across 58 namespaces**.

## What you get

- **Русский in the language selector.** It appears in *Settings → General → Language* next to the built-in languages, and switching applies immediately — no page reload.
- **Full coverage of the client UI.** Chat and step captions, the trajectory view, all settings sections, workspace and sidebar, background jobs, deliverables, plans and goals, the plugin manager, subagents and agent teams, voice input, shortcuts, document previews, dialogs.
- **Durable choice.** The Host stores the preference, so it survives restarts. With nothing stored yet, the pack follows the browser's own language list.
- **Graceful partial coverage.** Lookup walks `ru → en`, so any key without a translation shows its English text instead of a raw key name.
- **Nothing inside DSH is patched.** The pack is an ordinary client plugin installed into a profile, so DSH updates do not overwrite it and removal is a single command.

## Requirements

- DeepSeek Harness with the desktop or web GUI. Built and verified against `0.2.0-rc.2`.
- A profile that can install plugins. The desktop application ships the CLI at
  `%LOCALAPPDATA%\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd`; add that directory to `PATH` or call the file directly.

## Install

```powershell
# straight from this repository
dsh plugin --profile desktop add https://github.com/xISPx/dsh-locale-ru

# or from a local checkout
git clone https://github.com/xISPx/dsh-locale-ru
dsh plugin --profile desktop add ./dsh-locale-ru
```

Reload the GUI, open *Settings → General → Language* and pick **Русский**. The profile is recomposed by the running application; if the entry does not show up, restart DSH.

To remove the pack:

```powershell
dsh plugin --profile desktop remove dsh-locale-ru
```

## How it works

DSH localizes its interface through the client service `@deepseek-ai/dsh-client-locale`. Every client plugin registers its own dictionaries for the built-in languages:

```js
ctx.locale.register('chat', { zh, en })
```

A third-party client plugin may add a language and contribute dictionaries to any namespace:

```js
ctx.locale.addLanguage({ id: 'ru', label: 'Русский', fallback: 'en' })
ctx.locale.register('chat', 'ru', { /* key: translation */ })
```

Lookup then walks the fallback chain of the active language, repeating it in the `common` namespace before displaying the key itself. That chain is what makes partial translation safe, and it is why this pack only needs to ship the `ru` half of each dictionary.

This repository is that plugin. `cordis.patch.yml` declares a single loader row, `lib/index.js` is an empty host half (the pack is browser-only), and `lib/client.js` is the browser bundle that registers the language and the dictionaries.

## Repository layout

| Path | Purpose |
|---|---|
| `locales/ru.json` | The translations: namespace → key → text |
| `locales/en/*.json` | English source catalog extracted from DSH client bundles |
| `locales/zh-source.json` | DSH's own Chinese dictionaries, kept as a terminology reference |
| `lib/client.js` | Built browser bundle (generated by `build.mjs`) |
| `lib/index.js` | Host half — intentionally empty |
| `cordis.patch.yml` | The bundle patch: one `locale-ru` row |
| `build.mjs` | Builds `lib/client.js` from `locales/ru.json` and validates it |
| `tools/extract-bundles.ps1` | Extracts the client bundles from `app.asar` |
| `tools/extract-english.mjs` | Rebuilds `locales/en/` from those bundles |
| `tools/merge-ru.mjs` | Merges per-namespace staging files into `locales/ru.json` |
| `tools/check-ru.mjs` | Checks keys, placeholders and edge whitespace |
| `tools/lint-ru.mjs` | Checks terminology and style |
| `tools/selftest.mjs` | Loads the built bundle offline and inspects what it registers |
| `TRANSLATION.md` | Glossary and translation rules |

## Development

Any Node.js 18+ works; the DSH installation ships one at
`%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`.

```powershell
node tools/check-ru.mjs --merged     # structure: keys, placeholders, whitespace
node tools/lint-ru.mjs               # terminology and style
node build.mjs                       # locales/ru.json -> lib/client.js
node tools/selftest.mjs              # does the bundle register what it should?
```

`build.mjs --check` validates without writing, and reports both untranslated keys and any translation that lost a `{placeholder}`.

### After a DSH release

The English source lives inside DSH's client bundles, so a new DSH version may add, rename or drop keys:

```powershell
powershell -ExecutionPolicy Bypass -File tools\extract-bundles.ps1 -Dest "$env:TEMP\dsh-bundles"
node tools\extract-english.mjs "$env:TEMP\dsh-bundles" --write
node build.mjs --check
```

Then translate whatever `--check` reports and rebuild.

> The PowerShell script is saved as UTF-8 **with a BOM**: Windows PowerShell 5.1 otherwise reads its Cyrillic text as ANSI and fails to parse the file. Keep the BOM when editing it.

### A note on reloading

DSH publishes a client plugin bundle once, when its configuration is loaded, and derives the bundle revision from the file's timestamp and size. Editing `lib/client.js` on disk therefore does not reach a running application on its own — restart DSH, or reinstall the pack to publish it again:

```powershell
dsh plugin --profile desktop remove dsh-locale-ru
dsh plugin --profile desktop add ./dsh-locale-ru
```

## Contributing

Translations are plain JSON, so a fix is usually a one-line edit in `locales/ru.json` followed by `build.mjs`. Please read [TRANSLATION.md](TRANSLATION.md) first — it holds the glossary (session → «сессия», workspace → «рабочая область», subagent → «субагент», …) and two rules that are easy to get wrong:

- **Placeholders and edge whitespace are literal.** `{count}` must survive unchanged, and a string that starts or ends with a space keeps that space: such fragments are concatenated with their neighbours.
- **Only `*.one` and `*.other` exist for plurals.** The runtime picks `*.one` for exactly one and `*.other` for everything else, so `*.other` is phrased to avoid agreeing a noun with the numeral — «Запущено субагентов: {count}» reads correctly for 2, 5 and 21 alike.

## Limitations

- **Dictionary-backed text only.** Strings that DSH does not take from the locale registry stay English: CLI output, plugin package descriptions, and pnpm / Loader diagnostics.
- **Registry-held text is captured at registration.** A few labels, such as command descriptions, keep the language they were registered under until the plugin tree is rebuilt; slot-rendered copy follows switches live.
- **No plural rules or bidirectional layout.** The locale service supplies selection, persistence, browser matching, key fallback and `<html lang>` only.
- **Electron shell windows are not covered.** The welcome and update windows are static HTML inside `app.asar`, outside the locale system.
